# PRG: 저장 뒤 리다이렉트가 중복 저장을 막는 이유를 안다

사용자는 저장 뒤 F5를 세 번 눌러도 상품이 1개라고 예측했고, 이유로 리다이렉트된 GET은 데이터를 바꾸지 않는다고 답했다. 처음(진단)에는 PRG를 몰랐다.

## Evidence
- 예측 2개가 실행 결과와 맞았다. 수정 처리의 리다이렉트도 재현으로 확인했다.
- 놓친 것: `addAttribute`의 남은 값이 쿼리 파라미터가 되는 점(`/items/0`이라 예측, 실제 `/items/0?status=true`). "F5는 마지막 요청을 반복한다"는 말도 스스로 하지 못했다.

## Implications
- PRG를 다시 설명하지 않는다. 다음 회차의 로그인·로그아웃 뒤 리다이렉트는 이 개념 위에서 짧게 쓴다.
- 쿼리 파라미터 자리 구분과 "마지막 요청"은 회상 퀴즈로 한 번 더 묻는다.
