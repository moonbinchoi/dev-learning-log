용어집

spring-backend 트랙의 모든 레슨은 이 용어를 쓴다. 처음 나온 회차를 괄호에 적는다.

용어뜻
모델컨트롤러가 뷰(템플릿)에 넘기는 데이터 묶음. model.addAttribute("item", item)으로 넣으면 템플릿에서 ${item}으로 읽는다. 리다이렉트하면 사라진다. (1회차)
도메인 객체서비스가 다루는 핵심 대상을 나타내는 객체. 예: Item. 폼 객체와 구분한다. (1회차)
경로 변수URL 경로 안의 {이름} 자리(URI 템플릿 변수). /items/{itemId}의 itemId. 컨트롤러에서 @PathVariable로 받는다. (1회차)
PRG (Post/Redirect/Get)POST를 처리한 뒤 뷰를 바로 그리지 않고 리다이렉트로 응답해, 브라우저가 결과 페이지를 GET으로 다시 요청하게 하는 패턴. 새로고침해도 POST가 다시 전송되지 않는다. (1회차)
리다이렉트서버가 "이 주소로 다시 요청하라"고 응답하고, 브라우저가 그 주소로 새 요청을 보내는 것. 컨트롤러에서 뷰 이름 앞에 redirect:를 붙인다. (1회차)
쿼리 파라미터URL의 ? 뒤 이름=값 쌍. 예: /items/1?status=true. 템플릿에서 ${param.이름}으로 읽는다. (1회차)
커맨드 객체th:object로 폼에 지정한 객체. 폼의 각 칸이 이 객체의 필드에 대응한다. (1회차)
선택 변수 식*{필드}. th:object로 고른 객체의 필드를 가리킨다. *{itemName} = ${item.itemName}. (1회차)
바인딩요청 파라미터(문자열)를 객체 필드의 타입으로 바꿔 넣는 것. @ModelAttribute가 한다. (1회차)
BindingResult바인딩·검증 오류를 담는 객체. @ModelAttribute 파라미터 바로 다음에 두면 오류가 나도 컨트롤러가 호출된다. 모델에 자동으로 담긴다. (1회차)
FieldError특정 필드 하나의 오류. 사용자가 입력한 값(rejectedValue)을 함께 보관해서, 폼을 다시 그릴 때 입력값이 남는다. (1회차)
typeMismatch바인딩에서 타입 변환이 실패했을 때 스프링이 만드는 FieldError의 오류 코드. 예: 숫자 칸에 abc. (1회차)
Bean Validation필드에 @NotBlank·@Max 같은 애너테이션을 달아 검증 규칙을 선언하는 표준(Jakarta Validation). 구현체는 Hibernate Validator. (1회차)
폼 객체폼 데이터를 받기 위해서만 만든 객체(ItemSaveForm, ItemUpdateForm). 도메인 객체(Item)와 분리한다. (1회차)
글로벌 오류특정 필드가 아닌 객체 전체의 오류(ObjectError). bindingResult.reject(코드, 기본 문구)로 넣고, 템플릿은 ${#fields.globalErrors()}로 그린다. 예: 로그인 실패. (2회차)
쿠키서버가 응답의 Set-Cookie 헤더로 보내면 브라우저가 보관했다가, 같은 서버로 가는 요청마다 Cookie 헤더에 실어 보내는 이름=값. 브라우저 쪽에 있으므로 사용자가 바꿀 수 있다. (2회차)
세션중요한 데이터는 서버에 두고, 브라우저와는 추측할 수 없는 세션 ID로만 연결하는 방법. 서블릿의 HttpSession이 구현한다. (2회차)
세션 ID (JSESSIONID)세션 하나를 가리키는 무작위 값. 서블릿 세션은 JSESSIONID라는 쿠키로 주고받는다. (2회차)
세션 저장소세션 ID → 세션 객체를 보관하는 서버 메모리. 스프링 부트 기본 구성에서는 내장 톰캣이 관리한다. (2회차)
세션 타임아웃마지막 요청 뒤 이 시간 동안 요청이 없으면 서버가 세션을 지운다. 기본 30분, server.servlet.session.timeout으로 바꾼다. (2회차)
WAS (서블릿 컨테이너)웹 애플리케이션 서버. HTTP 요청을 받아 서블릿을 실행하고 필터·세션을 관리한다. 스프링 부트는 톰캣을 내장해 쓴다. (3회차)
싱글톤객체를 하나만 만들어 모든 요청이 함께 쓰는 방식. 필터·인터셉터·스프링 빈이 그렇다. 그래서 요청마다 다른 값을 필드에 두면 다른 요청과 섞인다. (3회차)
공통 관심사여러 기능이 공통으로 필요로 하는 일. 예: 상품 등록·수정·조회가 모두 로그인 검사를 필요로 한다. 웹 요청에 걸린 것은 필터나 인터셉터로 한곳에 둔다. (3회차)
DispatcherServlet스프링 MVC의 입구가 되는 서블릿. 요청 주소에 맞는 핸들러를 찾고, 인터셉터와 핸들러 어댑터를 차례로 불러 컨트롤러를 실행한다. (3회차)
핸들러요청을 처리할 대상. @Controller의 @GetMapping 메서드 하나가 핸들러다. 정적 파일 요청은 다른 핸들러가 맡는다. (3회차)
핸들러 어댑터DispatcherServlet 대신 핸들러를 실제로 호출하는 객체. 호출 전에 ArgumentResolver로 파라미터 값을 만든다. (3회차)
서블릿 필터서블릿 표준의 Filter. DispatcherServlet보다 앞에서 요청을 받는다. chain.doFilter()를 부르지 않으면 요청이 거기서 끝난다. (3회차)
필터 체인등록된 필터들이 순서대로 이어진 줄. 각 필터가 chain.doFilter()로 다음 필터를, 마지막 필터는 서블릿을 부른다. (3회차)
스프링 인터셉터스프링 MVC의 HandlerInterceptor. DispatcherServlet과 컨트롤러 사이에서 preHandle·postHandle·afterCompletion으로 불린다. preHandle이 false면 컨트롤러가 호출되지 않는다. (3회차)
화이트리스트검사 없이 항상 허용하는 경로 목록. 로그인 체크에서는 홈, 회원 가입, 로그인, CSS 같은 경로다. (3회차)
ArgumentResolverHandlerMethodArgumentResolver. 컨트롤러 파라미터 값을 만들어 넣는 객체. supportsParameter로 맡을 파라미터를 고르고 resolveArgument로 값을 만든다. (3회차)
