폼과 검증 요약

스프링 MVC 2편 2·4·5장. Spring Boot 4.1 기준. 용어는 용어집.

등록 처리의 뼈대

@PostMapping("/add")
public String addItem(@Validated @ModelAttribute("item") ItemSaveForm form,
                      BindingResult bindingResult,          // 검증 대상 바로 다음
                      RedirectAttributes redirectAttributes) {
    if (bindingResult.hasErrors()) {
        return "items/addForm";                             // 오류: 리다이렉트 없이 폼을 다시 그림
    }
    Item item = new Item();                                 // 폼 객체 → 도메인 객체
    item.setItemName(form.getItemName());
    item.setPrice(form.getPrice());
    item.setQuantity(form.getQuantity());
    Item saved = itemRepository.save(item);
    redirectAttributes.addAttribute("itemId", saved.getId()); // {itemId} 자리에 들어감
    redirectAttributes.addAttribute("status", true);          // 남은 것은 ?status=true
    return "redirect:/items/{itemId}";                      // PRG
}

규칙

주제규칙
PRG저장 성공 → 리다이렉트. 검증 실패 → 리다이렉트하지 않고 폼 뷰를 반환(입력값과 오류를 모델에 담은 채로).
RedirectAttributesaddAttribute 값은 리다이렉트 URL의 {이름}을 채우고, 남은 값은 쿼리 파라미터가 된다. 상세 화면은 th:if="${param.status}"로 메시지를 띄운다.
th:fieldid·name·value를 만든다. 오류가 있으면 value에 사용자가 입력한 값이 들어간다.
th:errors그 필드에 오류가 있을 때만 태그를 그리고 메시지를 출력한다.
th:errorclass그 필드에 오류가 있을 때만 CSS 클래스를 덧붙인다.
BindingResult 있음타입 오류가 나도 컨트롤러가 호출된다. typeMismatch FieldError가 담긴다.
BindingResult 없음컨트롤러가 호출되지 않고 400 오류.
검증 순서타입 변환 → 성공한 필드만 Bean Validation. 변환 실패 필드는 typeMismatch 하나만.
폼 객체 분리등록·수정은 받는 데이터와 검증 규칙이 다르다 → 폼 객체를 나누면 groups가 필요 없다.
@ModelAttribute("item")이름을 빼면 모델 키가 itemSaveForm이 되어 템플릿의 th:object="${item}"과 어긋난다.
