1회차 · 컨테이너 다루기

오늘의 성과: nginx 컨테이너 하나를 만들고, 들어가고, 멈추고, 다시 켜고, 지우면서 컨테이너가 지금 어느 상태인지 매 순간 말한다.

0회차에서 종료된 hello-world가 ps -a에 남아 있었다. 오늘은 그 이유를 수명주기로 정리한다. 7회차에 shop을 컨테이너에서 개발할 때도 "지금 컨테이너가 살아 있나, 멈췄나, 지워졌나"를 판단하는 것이 출발점이다. 용어는 용어집을 따른다.

1. 수명주기

  • 컨테이너는 주 프로세스가 끝나도 지워지지 않는다. 기본적으로 컨테이너의 파일 시스템은 컨테이너가 종료된 뒤에도 남는다. --rm을 붙인 경우에만 종료와 함께 삭제된다. (run --rm)
  • docker create는 이미지 위에 쓰기 가능한 컨테이너 레이어를 만든다. 컨테이너 안에서 생긴 변경은 여기에 쌓인다. (docker create)
  • Docker는 종료된 컨테이너를 스스로 다시 켜지 않는다. 재시작 정책의 기본값이 no다. (run --restart)

2. 오늘 쓰는 명령

명령하는 일
run -d --name web컨테이너를 백그라운드로 실행하고 ID를 출력한다. -d가 없으면 포그라운드로 돌아 터미널을 차지한다. --name이 없으면 이름이 무작위로 붙는다. (-d, Foreground and background)
exec -it web sh실행 중인 컨테이너 안에서 새 명령을 하나 더 실행한다. -i는 STDIN을 열어 두고, -t는 터미널(TTY)을 붙인다. (docker exec)
logs -f web주 프로세스의 STDOUT·STDERR를 보여 준다. -f를 붙이면 새 출력을 계속 따라간다. nginx 이미지는 access/error 로그를 stdout/stderr로 링크해 둔다. (Logging, logs -f)
stop web주 프로세스에 SIGTERM을 보내고, 유예 시간(Linux 기본 10초)이 지나도 끝나지 않으면 SIGKILL을 보낸다. 첫 신호는 이미지의 STOPSIGNAL로 바뀐다. nginx 이미지는 SIGQUIT이다(1회차 docker inspect로 확인). (docker stop)
start web멈춘 컨테이너를 다시 시작한다. 새로 만들지 않는다. (docker start)
rm web / rm -f컨테이너를 삭제한다. -f는 실행 중인 컨테이너를 SIGKILL로 끝내고 강제로 지운다. (rm -f)
run과 exec의 차이: run은 이미지로 새 컨테이너를 만든다. exec는 이미 실행 중인 컨테이너에 프로세스를 하나 더 띄운다. exec로 띄운 명령은 컨테이너가 재시작될 때 다시 실행되지 않는다.

3. 실습 — 예측하고 직접 친다

PowerShell에서 친다. 명령마다 예측을 먼저 말하고, 출력을 붙여 넣는다.

  1. 포그라운드로 실행한다.

    docker run --name fg nginx
    프롬프트가 다시 돌아올까? 로그가 좀 찍히면 Ctrl+C를 누른다. 그다음 docker ps -a에서 fg의 STATUS는 무엇일까?

  2. 백그라운드로, 이번엔 브라우저에서 접속할 수 있게 실행한다. -p 8081:80은 3회차에서 자세히 다룬다. 지금은 "호스트 8081 → 컨테이너 80"으로만 읽는다.

    docker run -d --name web -p 8081:80 nginx
docker ps
    첫 명령은 무엇을 출력하고 끝날까? docker ps의 STATUS 칸에는 무엇이 보일까?
  3. docker logs -f web

    이 상태에서 브라우저로 http://localhost:8081을 연다.

    터미널에 무엇이 새로 찍힐까? 이어서 Ctrl+C로 logs를 끊으면, 1번과 달리 web은 계속 running일까?
  4. docker exec -it web sh

    컨테이너 안 셸에서:

    echo hello > /tmp/mark.txt
exit
    exit로 셸을 빠져나온 뒤 docker ps에 web은 아직 running일까? 1번의 Ctrl+C와 무엇이 다를까?
  5. docker stop web
docker exec web cat /tmp/mark.txt
    stop은 몇 초쯤 걸릴까? 멈춘 컨테이너에 exec를 치면 어떻게 될까? (문서에 명시돼 있지 않다. 직접 재 본다.)
  6. docker start web
docker exec web cat /tmp/mark.txt
    4번에서 만든 mark.txt가 남아 있을까? 근거는?
  7. docker rm web
    web은 지금 running이다. 지워질까? (문서에 명시돼 있지 않다. 직접 재 본다.) 결과를 본 뒤 다음을 친다.
    docker rm -f web
docker rm fg
docker ps -a
