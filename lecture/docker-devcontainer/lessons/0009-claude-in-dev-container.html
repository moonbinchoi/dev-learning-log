8회차 · 컨테이너 안 Claude

오늘의 성과: shop dev container에 Claude Code를 설치하고 컨테이너 안에서 로그인한다. 컨테이너를 다시 만들어도 로그인이 유지되게 하고, 컨테이너 Claude가 보는 것과 못 보는 것을 직접 확인한다. 바꾼 devcontainer.json은 docker-devcontainer 브랜치에 커밋한다.

7회차에 shop의 worktree(projects/shop-docker-devcontainer, 브랜치 docker-devcontainer)를 dev container로 열었다. 오늘은 그 컨테이너에 Claude Code를 넣는다. 9회차에는 호스트 Claude가 이 컨테이너 Claude에게 일을 맡긴다. 용어는 용어집을 따른다.

1. 컨테이너 Claude는 어디서 도는가

  • 컨테이너 창에서는 Claude Code 확장 패널과 터미널의 claude가 둘 다 컨테이너 안에서 돈다. 둘은 같은 ~/.claude 설정을 쓴다. (Development containers, "How dev containers work with your editor")
  • 그래서 Claude가 실행하는 명령도 컨테이너 안에서 실행된다. 반면 프로젝트 파일 수정은 bind mount를 통해 호스트 저장소에 그대로 나타난다. (같은 문서, 첫 문단)
  • Claude는 CLAUDE.md를 지금 폴더와 그 위 폴더 전부에서 읽는다. (Memory, "How CLAUDE.md files load") 이 "위 폴더"는 컨테이너 안의 파일 시스템을 기준으로 한다. 컨테이너에 무엇이 마운트돼 있는지가 Claude가 읽는 것을 정한다. 실습 C에서 확인한다.

2. feature: 이미지에 도구를 더하는 조각

  • feature는 설치 스크립트를 묶은 단위다. devcontainer.json의 features에 적으면 컨테이너를 만들 때 이미지 위에 설치된다. 키는 feature ID이고, 값은 옵션 객체다. 옵션이 없으면 {}를 쓴다. (devcontainer.json reference, features)
  • Claude Code feature의 ID는 ghcr.io/anthropics/devcontainer-features/claude-code:1.0이다. 끝의 :1.0은 Claude Code 버전이 아니라 설치 스크립트의 버전이다. 설치되는 Claude Code는 늘 최신판이고, 설치된 뒤에는 스스로 업데이트한다. (Add Claude Code to your dev container)
  • VS Code에서 열면 이 feature가 Claude Code 확장도 함께 넣는다. (같은 절)
  • 이 feature는 npm으로 설치한다. 이미지에 Node.js가 없으면 Node.js부터 설치하고, 그 설치가 실패하면 Failed to install Node.js and npm이 나온다. 그때는 "ghcr.io/devcontainers/features/node:1": {}를 Claude Code feature 위에 더하고 다시 빌드한다. (같은 절, feature 소스)
  • features를 바꾸면 F1 → Dev Containers: Rebuild Container로 다시 만들어야 반영된다. (같은 절, 2단계)

3. 로그인을 다시 만들기에서 살리기

컨테이너 안에서 바꾼 파일은 쓰기 가능한 컨테이너 레이어에 쌓이고, 컨테이너를 지우면 함께 사라진다. Rebuild는 컨테이너를 새로 만들므로 홈 폴더(/home/vscode)에 쓴 것도 사라진다. 그대로 두면 Rebuild할 때마다 다시 로그인해야 한다. (Persist 절 첫 문장)

위치담는 것
~/.claude/사용자 설정 settings.json, 사용자 CLAUDE.md, 세션 기록, 리눅스에서는 인증 파일 .credentials.json
~/.claude.jsonOAuth 계정, 프로젝트별 신뢰 결정, 개인 MCP 서버. ~/.claude/ 폴더 밖의 파일이다

출처: Persist authentication and settings across rebuilds, Explore the .claude directory, Authentication

  • 그래서 ~/.claude에 named volume만 붙이면 ~/.claude.json은 볼륨 밖에 남아 Rebuild 때 사라지고, 로그인도 풀린다.
  • 문서의 해법은 두 가지를 함께 하는 것이다. ① ~/.claude에 named volume을 붙인다. ② 환경 변수 CLAUDE_CONFIG_DIR를 같은 경로로 지정한다. 이 변수를 지정하면 Claude Code는 설정 폴더를 그 경로로 바꾸고, .claude.json도 그 안에 쓴다. 그러면 로그인에 필요한 것이 모두 볼륨 안에 남는다. (같은 절, Environment variables, CLAUDE_CONFIG_DIR)
  • 볼륨 이름에 ${devcontainerId}를 넣으면 프로젝트마다 볼륨이 따로 생긴다. 이 변수는 dev container마다 고유한 ID로 바뀌고, Rebuild해도 같은 값을 유지한다. (devcontainer.json reference, 변수 표) Anthropic 참고 설정도 claude-code-config-${devcontainerId}를 쓴다. (Persist 절)
  • 문서 예시는 remoteUser가 node인 경우라 /home/node/.claude를 쓴다. "remoteUser의 홈 폴더로 바꾸라"고 적혀 있다. shop 컨테이너의 사용자는 6회차에 whoami로 확인한 vscode다. (같은 절)

4. containerEnv vs remoteEnv

키누구에게 보이나바꾸면
containerEnvDocker 컨테이너 자체에 들어간다. 컨테이너 안에서 뜨는 모든 프로세스가 본다Rebuild해야 반영된다
remoteEnvVS Code와 그 하위 프로세스(터미널, 태스크, 디버거)에만 들어간다Rebuild 없이 바꿀 수 있다

출처: devcontainer.json reference("We recommend using containerEnv (over remoteEnv) as much as possible since it allows all processes to see the variable"), VS Code: Environment variables

9회차에는 호스트에서 docker exec로 컨테이너 안에 claude를 띄운다. 이 프로세스는 VS Code가 띄운 것이 아니다. 문서에는 docker exec에 대한 언급이 없다. 그래서 오늘 실습 B-3에서 두 키의 차이를 직접 잰다. remoteEnv는 이 측정에만 쓰고 커밋 전에 지운다.

문법 예시 (오늘 과제와 다른 Python 앱)

{
  "name": "flask-demo",
  "image": "mcr.microsoft.com/devcontainers/python:3.12",
  "features": {                                   // feature ID: 옵션 객체
    "ghcr.io/devcontainers/features/node:1": {}   // 옵션 없음 = {}
  },
  "mounts": [
    "source=flask-pip-cache,target=/home/vscode/.cache/pip,type=volume",
    "source=flask-hist-${devcontainerId},target=/home/vscode/.hist,type=volume"
  ],                                              // 문자열 하나 = 마운트 하나
  "containerEnv": {
    "HISTFILE": "/home/vscode/.hist/bash_history" // 컨테이너의 모든 프로세스가 본다
  },
  "remoteEnv": {
    "FLASK_DEBUG": "1"                            // VS Code 터미널 등에만
  },
  "postCreateCommand": "sudo chown vscode /home/vscode/.cache/pip /home/vscode/.hist"
}                                                 // chown은 경로를 여러 개 받는다

주석(//)은 설명용이다. 오늘 파일에는 쓰지 않는다.

5. 권한 모드

Claude가 도구(파일 수정, 명령 실행)를 쓰기 전에 사람에게 묻는 정도를 정한다. (Permission modes)

모드묻지 않고 하는 것문서가 말하는 용도
default읽기만모든 동작을 직접 검토할 때
acceptEdits읽기, 파일 수정, mkdir·mv 같은 흔한 파일 명령검토 중인 코드를 고칠 때
plan읽기(+auto mode를 쓸 수 있으면 분류기가 승인한 명령)바꾸기 전에 둘러볼 때
auto전부. 대신 분류기가 실행 전에 안전 검사를 한다긴 작업
dontAsk작업 폴더 안 파일 읽기와 미리 허용한 도구. 물어야 할 것은 거부한다CI, 스크립트
bypassPermissions전부. 확인도 안전 검사도 없다격리된 컨테이너와 VM에서만
  • 시작 모드: v2.1.283 이상은 대화형 세션을 auto로 시작한다(계정·모델이 auto mode를 쓸 수 있을 때). auto의 분류기는 실행 전에 동작을 검사하는 별도 모델이다. default는 화면에 Manual로 표시되고 manual로도 쓸 수 있다. (같은 문서, 머리말)
  • 세션 중에는 Shift+Tab으로 바꾼다. auto에서 누르면 default가 되고, 그다음 acceptEdits → plan을 돈다. 입력창 아래 상태 표시줄에 ⏸ manual mode on, ⏵⏵ accept edits on, ⏸ plan mode on, ⏵⏵ auto mode on처럼 보인다. 시작할 때는 claude --permission-mode default처럼 옵션으로 준다. (같은 문서)
  • --dangerously-skip-permissions는 bypassPermissions와 같다. 리눅스에서 root나 sudo로는 이 모드로 시작하지 못한다. dev container 문서는 그래서 컨테이너 사용자가 root가 아닌지 확인하라고 한다. (같은 문서, Run without permission prompts)
  • 격리가 막는 것과 못 막는 것. 명령 실행은 컨테이너 안으로 한정된다. 다만 문서는 "어떤 시스템도 모든 공격을 완전히 막지는 못한다"고 먼저 경고한다. 그러나 bind mount된 프로젝트 파일은 호스트의 실제 파일이라 고칠 수 있다. 네트워크도 막지 않으면 어디든 나갈 수 있다. 확인을 끈 상태에서 악성 프로젝트를 열면 컨테이너 안의 모든 것, 곧 ~/.claude의 인증 정보까지 빠져나갈 수 있다. 그래서 문서는 다음을 권한다. 믿을 수 있는 저장소에만 쓴다. ~/.ssh 같은 호스트 비밀을 마운트하지 않는다. 확인을 줄이고 싶으면 auto mode를 고려한다. (같은 절, 문서 맨 위 경고)

7. 실습 — 예측하고 직접 친다

7회차와 같은 두 창이다. Claude 창(호스트, 이 강의)과 실습 창(projects/shop-docker-devcontainer를 컨테이너로 연 창)을 쓴다. 실습 창 터미널 출력은 복사해서 붙여 넣는다.

A. devcontainer.json 고치기

  1. 실습 창을 연다. 이 명령은 폴더를 호스트에서 연다. 오른쪽 아래 알림의 Reopen in Container를 누르거나 F1 → Dev Containers: Reopen in Container로 컨테이너로 다시 연다. 왼쪽 아래에 Dev Container: shop이 보이면 된다.

    code -n E:\Study\Inflearn\projects\shop-docker-devcontainer

    실습 창 터미널(Ctrl+`)에서 시작 상태를 본다. "nothing to commit, working tree clean"이 아니면 출력을 Claude에게 붙여 넣고 멈춘다.

    git status

    .devcontainer/devcontainer.json을 직접 고친다. 기존 키는 그대로 두고 아래만 더한다.

    키더할 것
    features새 키. ghcr.io/anthropics/devcontainer-features/claude-code:1.0 하나, 옵션 없음
    mounts두 번째 문자열: 볼륨 claude-code-config-${devcontainerId}을 /home/vscode/.claude에 (type=volume)
    containerEnv기존 객체에 CLAUDE_CONFIG_DIR = "/home/vscode/.claude". 객체를 하나 더 만들지 않는다
    remoteEnv임시. LAB_WHERE = "remote". 측정이 끝나면 지운다
    postCreateCommand직접 정한다. 아래 예측을 먼저 푼다
    먼저 한 줄로 다시 말해 보자. 7회차의 postCreateCommand sudo chown vscode /home/vscode/.gradle는 왜 필요했나? 그 이유를 놓고 보면 오늘 새로 붙이는 볼륨 /home/vscode/.claude에도 필요할까? 필요하다고 판단하면 4절 예시처럼 경로를 하나 더 붙인다.

    리뷰 받기 전 이름 대조:

    • mounts의 target과 CLAUDE_CONFIG_DIR 값이 글자 하나까지 같은가
    • ${devcontainerId}의 대소문자(I는 대문자)와 중괄호
    • mounts 두 문자열 사이에 쉼표가 있고, 마지막 항목 뒤에는 없는가

    다 쓰면 Claude에게 리뷰를 받는다.

B. 다시 만들고 확인

  1. 실습 창에서 F1 → Dev Containers: Rebuild Container. 끝나면 Claude가 docker inspect로 새 컨테이너의 마운트 목록을 읽는다.

    지금(7회차 끝) 이 컨테이너에 붙어 있던 것: bind mount 둘(worktree 폴더 → /workspaces/shop-docker-devcontainer, common dir projects\shop\.git → /workspaces/shop/.git), 볼륨 둘(shop-gradle-home → /home/vscode/.gradle, vscode → /vscode. 6회차 프로세스 목록으로 보면 VS Code Server가 들어 있다).

    볼륨은 몇 개 붙을까? shop-gradle-home은 7회차 것을 다시 쓸까, 새로 생길까? 새 Claude 볼륨의 실제 이름에서 ${devcontainerId} 자리에는 무엇이 들어갈까?

  2. 실습 창 터미널에서 친다. 위에서부터 Node.js 버전, Claude Code 버전, ~/.claude 폴더 자체의 소유자(세 번째 칸), 환경 변수 두 개의 값이다.

    node --version
claude --version
ls -ld ~/.claude
echo $CLAUDE_CONFIG_DIR
echo $LAB_WHERE
    node --version은 버전을 출력할까, command not found일까? (2절) ~/.claude의 소유자는 vscode일까 root일까? 두 echo는 각각 무엇을 출력할까?

    java 이미지에 Node.js가 원래 없었는지는 위 출력으로는 알 수 없다. feature가 설치한 것도 똑같이 보이기 때문이다. Claude가 빌드 기록에서 Node.js 설치 줄을 찾아 확인한다.

    이어서 Claude가 호스트에서 VS Code를 거치지 않고 같은 두 변수를 읽는다.

    docker exec <컨테이너> printenv CLAUDE_CONFIG_DIR LAB_WHERE
    4절의 표를 놓고 보면 몇 줄이 나올까? 어느 값이 빠질까? 그 결과가 9회차에 어떤 의미가 있을까?

C. 로그인하고, 보이는 것 확인

  1. 실습 창 터미널에서 claude를 실행하고 안내대로 로그인한다. 브라우저 로그인이 끝났는데도 터미널이 계속 기다리면 브라우저에 보이는 코드를 복사해 Paste code here if prompted에 붙여 넣는다. 에디터의 포트 포워딩이 브라우저의 로그인 결과(localhost 콜백)를 컨테이너로 전달하지 못하면 이렇게 된다. (Development containers, Note)

    로그인 직후 입력창 아래 상태 표시줄에는 어떤 권한 모드가 보일까? (5절 "시작 모드")

    로그인 뒤 /exit로 나와서 본다. 위는 ~/.claude 폴더 안, 아래는 홈 폴더의 숨김 파일까지 전부다.

    ls -a ~/.claude
ls -a ~
    .claude.json은 홈(~)에 있을까, ~/.claude/ 안에 있을까? 인증 파일 .credentials.json은 어디 있을까? (3절)

  2. 다시 claude를 실행하고 /context를 친다. Memory files 아래를 본다. 다 보면 Esc로 닫고 /exit로 나와서 컨테이너의 /workspaces 폴더 목록을 본다.

    ls /workspaces

    먼저 재료를 한 줄로 다시 말해 보자. 컨테이너에 bind mount된 호스트 폴더는 둘뿐이다: worktree 폴더 → /workspaces/shop-docker-devcontainer, common dir projects\shop\.git → /workspaces/shop/.git. Claude는 지금 폴더와 그 위 폴더 전부에서 CLAUDE.md를 읽는다(1절).

    호스트에서는 E:\Study\Inflearn\CLAUDE.md가 이 worktree의 위 폴더에 있다. 컨테이너 Claude의 Memory files에 그 파일이 나올까? 호스트의 전역 설정(C:\Users\…\.claude\CLAUDE.md)은? /workspaces에는 무엇이 있고, courses는 보일까?

D. 권한 모드

  1. Manual 모드(default)로 세션을 시작하고, 이렇게 시킨다.

    claude --permission-mode default
    ./gradlew build 를 실행하고 결과를 한 줄로 알려 줘
    바로 실행할까, 먼저 물을까? (5절 표의 default)

    물으면 허용해서 실행시킨다. 그다음 Shift+Tab을 몇 번 누르며 상태 표시줄의 모드 이름을 본다. 확인한 뒤 /exit.

E. Rebuild 뒤에도 로그인이 남는가

  1. 다시 F1 → Dev Containers: Rebuild Container. 끝나면 터미널에서 claude를 실행한다.

    로그인 화면이 다시 뜰까? 근거는 컨테이너·볼륨·CLAUDE_CONFIG_DIR 세 가지 중 어느 것인가?

    확인한 뒤 /exit.

F. 정리하고 커밋

  1. devcontainer.json에서 remoteEnv 블록을 지운다(앞 줄 끝 쉼표도 확인). 실습 창 터미널에서 본다.

    git status
git diff
    git status에 devcontainer.json 말고 다른 파일이 나올까? ~/.claude의 파일들은 git에 보일까? (그 폴더는 어디에 마운트된 무엇인가)

    diff를 Claude와 함께 본 뒤 커밋한다.

    git add .devcontainer/devcontainer.json
git commit -m "dev container에 Claude Code 추가"

    실습 창은 열어 둔다. 9회차에 이 컨테이너를 쓴다.

실습에서 드러난 것 (2026-10-20). 첫 Rebuild는 Failed to install Node.js and npm으로 실패했다. java:25-trixie에는 Node가 없고, feature가 설치한 Debian nodejs(20.19.2)에는 npm이 없었다. 2절의 방법대로 "ghcr.io/devcontainers/features/node:1": {}를 위에 더해 해결했다(Node 24.22.0). feature를 쓰면 .devcontainer/devcontainer-lock.json이 생겨 feature마다 받은 버전과 체크섬을 적는다(lockfile 스펙). 함께 커밋했다(21b4dda). 로그인하자 claude.ai 계정의 커넥터(Gmail, Notion 등)가 /mcp에 나타났다. 계정에 연결된 외부 서비스는 컨테이너 격리 밖이다(MCP, "Use MCP servers from Claude.ai").

8. 남겨 둘 것과 다음

  • 남긴다: Claude 볼륨 claude-code-config-…(로그인 상태), shop-gradle-home, worktree와 브랜치.
  • 9회차: 호스트에서 docker exec … claude -p로 컨테이너 Claude에게 이슈 파일을 맡기고, 결과 커밋을 git diff로 리뷰한다.

실무에서는 팀 정책(텔레메트리 끄기, 버전 고정, 네트워크 출구 제한)도 같은 devcontainer.json과 이미지에 넣어 모든 팀원에게 같은 환경을 준다. 오늘은 다루지 않는다. (Enforce organization policy, Restrict network egress)
