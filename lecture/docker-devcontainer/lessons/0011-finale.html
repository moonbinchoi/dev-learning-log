1. devcontainer CLI: 폴더로 컨테이너를 찾는다

  • Dev Container 명세의 공식 CLI다. npm 패키지 @devcontainers/cli로 설치하고, 명령 이름은 devcontainer다. (devcontainers/cli, VS Code: dev container CLI) 2026-10-21 기준 최신은 0.89.0이다(npm).
  • VS Code 문서는 설치할 때 의존성 하나를 빌드하느라 Python, Node.js 14 이상, C/C++이 필요하다고 적는다. 호스트에는 Node 24.19.0과 Python이 있다. C/C++ 도구가 없어서 설치가 실패할 수도 있다. 실패하면 출력을 붙여 넣는다.
  • 오늘 쓰는 하위 명령 두 개:
    명령하는 일
    devcontainer updevcontainer.json 설정을 적용해 컨테이너를 띄운다. 오늘은 쓰지 않는다
    devcontainer execuserEnvProbe, remoteUser, remoteEnv 등을 적용해 컨테이너에서 명령을 실행한다

    출처: devcontainers/cli README의 명령 목록. 맞는 컨테이너가 없을 때 exec가 무엇을 하는지는 README에 없어서 실습 A에서 본다.

  • 컨테이너를 찾는 방법. exec는 컨테이너 이름 대신 라벨로 찾는다. 라벨 devcontainer.local_folder(호스트 폴더)와 devcontainer.config_file(설정 파일 경로)가 --workspace-folder에서 계산한 값과 같은 컨테이너를 찾는다. Windows에서는 비교 전에 드라이브 문자만 소문자로 바꾼다. (CLI 소스 src/spec-node/utils.ts)
  • 지금 shop 컨테이너를 docker inspect로 보면 VS Code가 붙인 라벨이 이렇다. 
    devcontainer.local_folder = e:\Study\Inflearn\projects\shop-docker-devcontainer
devcontainer.config_file  = e:\Study\Inflearn\projects\shop-docker-devcontainer\.devcontainer\devcontainer.json
  • docker exec와 다른 점. 위 표처럼 exec는 remoteUser, remoteEnv, userEnvProbe(사용자 로그인 셸의 환경 변수를 읽어 오는 설정)를 적용한다. -u·-w 같은 옵션은 없다(CLI 소스 devContainersSpecCLI.ts의 옵션 목록). 환경 변수는 --remote-env 키=값으로 더한다.
    옵션뜻
    --workspace-folder 경로이 호스트 폴더의 dev container를 찾는다
    --container-id ID라벨 대신 컨테이너 ID로 지정한다
    --remote-env 키=값이 명령에만 환경 변수를 더한다(docker exec -e 자리)

문법 예시 (오늘 과제와 다른 Node 프로젝트)

# 호스트에 CLI를 전역으로 설치하고 확인
npm install -g @devcontainers/cli
devcontainer --version
# C:\work\blog의 dev container를 라벨로 찾아, 환경 변수 CI=true를 더해, 그 안에서 npm test 실행
devcontainer exec --workspace-folder C:\work\blog --remote-env CI=true npm test

2. 볼륨 위에 파일 하나 bind mount

  • 왜 궁금한가. CLAUDE_CONFIG_DIR를 지정하면 ~/.claude 아래 모든 파일이 그 폴더로 간다. (Explore the .claude directory) 사용자 CLAUDE.md도 그렇다. shop 컨테이너에서는 /home/vscode/.claude/CLAUDE.md이고, 이 경로는 볼륨 claude-code-config-… 안이다. 호스트의 파일 하나를 거기에 붙이면 컨테이너 Claude가 호스트와 같은 지침을 읽을까?
  • 문서로 확인한 것:
    사실출처
    bind mount의 source는 파일이어도 된다. --mount로 줬는데 source가 없으면 오류다(-v는 폴더를 만든다)Bind mounts
    비어 있지 않은 경로에 bind mount하면 원래 내용은 가려진다Bind mounts
    빈 볼륨을 이미지에 내용이 있는 경로에 붙이면 그 내용이 볼륨으로 복사된다Volumes
  • 문서에 없는 것(오늘 잰다): 마운트 대상 하나가 다른 마운트 대상 안에 있을 때의 순서와 결과. 호스트에서 파일을 고쳤을 때 컨테이너에 보이는지. 포럼에는 편집기가 새 파일을 만들어 바꿔치기하면 컨테이너가 옛 파일을 계속 본다는 보고가 있다. (Docker forum) 공식 문서가 아니라서 확인 거리로 둔다.

문법 예시 (오늘 과제와 다른 경로)

# 볼륨 cache를 /cache에 붙이고, 호스트 파일 C:\cfg\app.ini를 그 안의 /cache/app.ini에 붙여, 그 내용을 출력
docker run --rm `
  --mount type=volume,source=cache,target=/cache `
  --mount type=bind,source=C:\cfg\app.ini,target=/cache/app.ini `
  alpine:3.22 cat /cache/app.ini

# PowerShell 파일 명령 (C:\tmp 예시)
New-Item -ItemType Directory C:\tmp\demo          # 폴더 만들기
Set-Content C:\tmp\demo\a.txt "hello"             # a.txt에 hello를 쓴다(없으면 만든다)
Get-Content C:\tmp\demo\a.txt                     # 내용 출력
Move-Item -Force C:\tmp\demo\a.txt C:\tmp\b.txt   # 옮기기. b.txt가 있으면 덮어쓴다
Get-ChildItem C:\tmp\demo                         # 폴더 안 목록

# 컨테이너 안 셸로 두 명령을 한 번에: >>는 끝에 덧붙이기, >는 새로 쓰기
docker exec web sh -c "echo line >> /tmp/log.txt; echo new > /tmp/x.txt"

--mount 값은 쉼표로 이은 키=값이다. shop devcontainer.json의 mounts 문자열과 같은 문법이다. (Bind mounts, Options for --mount)

3. README 리뷰 관점

9회차에는 README를 읽고 "고칠 것 없음"이라고 했다. 리뷰는 틀린 문장만 찾는 일이 아니다. 아래 네 관점으로 한 번씩 훑는다.

관점묻는 것
근거문장마다 저장소 파일이나 실측이 뒷받침하는가. 뒷받침이 없으면 지우거나 근거를 단다
호스트만 아는 맥락컨테이너 Claude가 몰랐던 사실(포트를 고른 이유, VS Code 사용자 설정, worktree를 만든 방식)이 맞게 들어갔는가
앞 실측과의 대조7~9회차에 잰 사실과 맞는가. 처음 쓰는 사람이 부딪힐 실측 결과가 빠지지 않았는가

대조할 실측(7~9회차):

  • Dev Containers는 사용자 .gitconfig만 컨테이너로 복사한다. 호스트 시스템 설정의 core.autocrlf=true는 따라오지 않아서, .gitattributes 맨 위에 * text=auto eol=lf를 두었다.
  • worktree는 git worktree add --relative-paths로 만들었다. .git 파일에 상대 경로가 적힌다.
  • java:25-trixie 이미지에는 Node가 없다. Claude Code feature의 자동 Node 설치가 실패해서 Node feature를 함께 넣었다.
  • 호스트에서 docker exec로 들어가면 root다. -u vscode를 줘야 한다.
  • ${devcontainerId}는 Rebuild해도 바뀌지 않는다.

A. devcontainer exec가 VS Code의 컨테이너를 쓰는지

  1. CLI를 설치하고 버전을 본다.

    npm install -g @devcontainers/cli
devcontainer --version

  2. worktree 폴더를 변수에 담고, 사용자·작업 폴더·HOME을 본다. 이어서 컨테이너 목록을 본다.

    $wt = "E:\Study\Inflearn\projects\shop-docker-devcontainer"
devcontainer exec --workspace-folder $wt whoami
devcontainer exec --workspace-folder $wt pwd
devcontainer exec --workspace-folder $wt printenv HOME
docker ps -a --format "{{.Names}}  {{.Status}}"
    재료: 1절의 라벨 값과 찾는 방법(드라이브 문자만 소문자로 바꿔 비교). CLI README가 말하는 remoteUser 적용. shop의 remoteUser는 이미지 라벨에서 온 vscode이고, worktree는 컨테이너의 /workspaces/shop-docker-devcontainer에 붙어 있다. 지금 docker ps -a에는 clever_northcutt 하나만 있다. whoami와 printenv HOME은 무엇을 출력할까? 명령 뒤 컨테이너는 몇 개일까?

    확인 거리: pwd. CLI 소스에는 컨테이너의 작업 공간 폴더에서 실행한다고 되어 있다. 문서에는 없어서 결과로 본다.

  3. 같은 명령을 main worktree(projects\shop, 브랜치 master)에 친다. 이 폴더에도 .devcontainer/devcontainer.json이 있지만, 이 폴더로 연 컨테이너는 없다.

    devcontainer exec --workspace-folder E:\Study\Inflearn\projects\shop whoami
docker ps -a --format "{{.Names}}  {{.Status}}"
    이 폴더의 라벨을 단 컨테이너는 없다. exec가 컨테이너를 새로 만들까, 오류로 끝날까? 컨테이너 수는 바뀔까? (문서에 없어서 실측으로 정한다)

B. 볼륨 위에 파일 하나 bind mount

shop 설정은 바꾸지 않는다. docker-lab 폴더에서 버리는 컨테이너로 잰다.

  1. 위에서부터: docker-lab으로 이동, 시험 폴더와 파일 만들기, 빈 볼륨 lab-vol 만들기, 볼륨을 /data에 붙이고 호스트 파일을 /data/note.md에 붙여 30분 동안 켜 두기. alpine:3.22는 로컬에 없어서 처음 한 번 내려받는다.

    cd E:\Study\Inflearn\projects\docker-lab
New-Item -ItemType Directory mount-test
Set-Content mount-test\note.md "v1 from host"
docker volume create lab-vol
docker run -d --name mount-test `
  --mount type=volume,source=lab-vol,target=/data `
  --mount type=bind,source=E:\Study\Inflearn\projects\docker-lab\mount-test\note.md,target=/data/note.md `
  alpine:3.22 sleep 1800

    줄 끝 `는 PowerShell의 줄 잇기다. 뒤에 공백이나 주석이 오면 안 된다. 네 줄을 한꺼번에 붙여 넣는다.

  2. 컨테이너 안에서 note.md 내용과 /data 목록을 본다.

    docker exec mount-test cat /data/note.md
docker exec mount-test ls -l /data
    컨테이너는 v1 from host를 볼까? /data에는 무엇이 있을까?

  3. 컨테이너 안에서 note.md에 한 줄을 덧붙이고, 새 파일 other.txt를 만든다. 그다음 호스트에서 본다.

    docker exec mount-test sh -c "echo from-container >> /data/note.md; echo hi > /data/other.txt"
Get-Content mount-test\note.md
Get-ChildItem mount-test
    덧붙인 줄은 호스트 파일에 보일까? other.txt는 호스트의 mount-test 폴더에 생길까, 다른 곳에 생길까?

  4. 호스트에서 같은 파일에 바로 쓴다.

    Set-Content mount-test\note.md "v2 written directly"
docker exec mount-test cat /data/note.md
    컨테이너는 v2를 볼까?

  5. 이번에는 새 파일을 만들어 바꿔치기한다. 편집기가 저장할 때 이렇게 하는 경우가 있다는 보고가 있다.

    Set-Content mount-test\note.tmp "v3 replaced"
Move-Item -Force mount-test\note.tmp mount-test\note.md
Get-Content mount-test\note.md
docker exec mount-test cat /data/note.md
    재료: 2절의 포럼 보고(공식 문서 아님). 호스트는 v3를 보고, 컨테이너는 무엇을 볼까?

  6. 컨테이너를 지우고, 볼륨만 붙인 새 컨테이너로 볼륨 안을 본다.

    docker rm -f mount-test
docker run --rm --mount type=volume,source=lab-vol,target=/data alpine:3.22 ls -l /data
    볼륨에 other.txt가 있을까? note.md는 있을까, 있다면 크기는?

    결과를 놓고 이야기한다. shop의 /home/vscode/.claude/CLAUDE.md에 호스트 파일을 붙일 가치가 있나? 붙인다면 무엇을 조심해야 하나?
