오늘의 성과: docker run hello-world를 두 번 치고, 이미지 1개와 컨테이너 2개가 생긴 이유를 설명한다.

미션의 첫 줄은 "JDK·DB 환경을 코드로 고정해 어느 PC에서나 같은 환경을 띄운다"였다. 그 환경이 담기는 그릇이 이미지, 실제로 띄운 것이 컨테이너다. 오늘은 이 둘을 구분하고, Windows에서 Docker가 어디서 도는지 본다. 용어는 용어집을 따른다.

1. 이미지와 컨테이너

이미지컨테이너
정체컨테이너를 돌리는 데 필요한 파일·바이너리·라이브러리·설정을 묶은 패키지격리된 프로세스
변경불변. 고치려면 새 이미지를 만들거나 위에 레이어를 얹는다실행하면서 생긴 변경은 그 컨테이너에만 남는다
개수하나같은 이미지에서 여러 개

출처: What is an image?, What is a container?

Java로 비유하면 이미지는 클래스, 컨테이너는 new로 만든 객체에 가깝다. 비유일 뿐이니 "이미지는 불변"이라는 공식 정의를 기준으로 삼는다.

2. 컨테이너 vs VM

VM은 "자체 커널, 하드웨어 드라이버, 프로그램, 애플리케이션을 갖춘 운영체제 전체"다. 컨테이너는 "실행에 필요한 파일을 가진 격리된 프로세스"이고, 여러 컨테이너가 같은 커널을 공유한다. 그래서 같은 하드웨어에서 더 많은 앱을 돌린다. (What is a container?)

그런데 Windows 커널은 리눅스 컨테이너가 공유할 리눅스 커널이 아니다. 그래서 다음 구조가 필요하다.

4. 실습 — 예측하고 직접 친다

명령마다 먼저 예측을 말한 뒤 PowerShell에서 친다. 출력은 Claude와 함께 읽는다.

  1. Docker Desktop을 실행하고(작업 표시줄 고래 아이콘이 멈출 때까지), 다음을 친다.

    docker version
    출력은 Client와 Server 두 부분으로 나뉜다. 각 부분의 OS/Arch는 무엇일까? 둘이 같을까?

  2. Dev Containers 확장을 설치한다(6회차부터 쓴다). 확장 ID는 ms-vscode-remote.remote-containers다. (설치 안내)

    code --install-extension ms-vscode-remote.remote-containers
  3. docker run hello-world
    처음 치면 메시지 본문 전에 무엇이 먼저 출력될까? 출력의 4단계 중 위 그림의 ①②③은 각각 몇 번일까?

  4. 같은 명령을 한 번 더 친다.

    docker run hello-world
    첫 번째와 무엇이 다를까? 왜?
  5. docker ps
docker ps -a
docker images
    세 명령에 hello-world가 각각 몇 줄씩 보일까?

  6. 0~6회차 실습 repo를 만든다.

    mkdir E:\Study\Inflearn\projects\docker-lab
cd E:\Study\Inflearn\projects\docker-lab
git init
