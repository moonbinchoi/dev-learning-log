7회차 · shop에 dev container 적용

오늘의 성과: shop의 새 브랜치를 별도 폴더(worktree)로 꺼내고, 그 폴더를 dev container로 열어 ./gradlew build를 통과시킨다. 컨테이너 안에서 git이 동작하게 만든 뒤, .devcontainer/devcontainer.json을 그 브랜치에 커밋한다.

6회차에는 연습용 docker-lab에 dev container를 붙였다. 오늘은 포트폴리오 저장소인 shop에 붙인다. shop은 spring-backend 트랙이 projects/shop 폴더에서 master 브랜치로 쓰고 있다. 그 폴더를 건드리지 않으려고 git 브랜치와 worktree를 처음 쓴다. 용어는 용어집을 따른다.

1. 브랜치와 HEAD

  • 커밋은 그 시점의 파일 전체 스냅샷이고, 바로 앞 커밋을 가리킨다.
  • 브랜치는 커밋 하나를 가리키는 가벼운 포인터다. 실제로는 커밋 ID 40자를 담은 작은 파일이다. 새 커밋을 만들면 지금 브랜치가 그 커밋으로 옮겨 간다. (Branches in a Nutshell)
  • HEAD는 "지금 내가 있는 브랜치"를 가리키는 포인터다. 브랜치를 새로 만들기만 하면 HEAD는 옮겨 가지 않는다. (같은 문서)
  • 그래서 브랜치를 만드는 것은 파일을 복사하는 일이 아니다. 같은 커밋에 이름표를 하나 더 붙이는 일이다.

2. worktree: 한 저장소, 작업 폴더 둘

  • git 저장소 하나에 작업 폴더(worktree)를 여러 개 붙일 수 있다. 폴더마다 다른 브랜치를 꺼내 놓고 동시에 작업한다. 원래 폴더는 main worktree, 새로 붙인 폴더는 linked worktree다. (git-worktree)
  • 커밋과 브랜치는 공유한다. 한 폴더에서 만든 커밋은 다른 폴더에서도 git log로 보인다.
  • 같은 브랜치를 두 worktree에서 동시에 꺼낼 수 없다. git이 거부한다. (같은 문서, add)
  • linked worktree 맨 위의 .git은 폴더가 아니라 파일이다. 안에는 main worktree의 .git/worktrees/<이름> 경로가 적혀 있고, git은 이 경로를 따라가 커밋을 찾는다. 기본은 절대 경로다. (git-worktree: DETAILS)
  • 커밋과 브랜치가 실제로 저장된 main worktree의 .git 폴더를 git 문서는 common dir(공통 폴더)라 부른다. 모든 worktree가 이 폴더 하나를 함께 쓴다. (같은 DETAILS 절)
  • --relative-paths를 주면 그 경로를 상대 경로로 적는다. (git-worktree, add의 옵션) 같은 일을 하는 설정 worktree.useRelativePaths의 설명에는 "켜면 extensions.relativeWorktrees도 켜져 옛 git과 호환되지 않는다"고 적혀 있다. (같은 문서, CONFIGURATION 절) 옵션도 이것을 켜는지는 실습 1단계에서 확인한다. 켜진다면 그 값은 spring-backend도 쓰는 projects/shop/.git/config에 들어간다. 호스트 git은 2.55다.

다른 저장소로 본 예시 (저장소 blog, 브랜치 hotfix):

# main worktree 폴더로 간다
cd C:\code\blog
# 새 브랜치 hotfix를 만들어 ..\blog-hotfix 폴더로 꺼낸다
git worktree add --relative-paths -b hotfix ..\blog-hotfix
# 줄마다: 경로  커밋  [브랜치]
git worktree list
#   C:/code/blog         9f3c1a2 [main]
#   C:/code/blog-hotfix  9f3c1a2 [hotfix]

오늘 worktree는 --relative-paths로 만든다. 왜 그래야 하는지는 실습 C에서 확인한다.

3. shop의 devcontainer.json

출발점은 조사 문서(docs/research/devcontainer-claude.md)의 초안이다.

{
  "name": "shop",
  "image": "mcr.microsoft.com/devcontainers/java:25-trixie",
  "remoteUser": "vscode",
  "forwardPorts": [8080],
  "mounts": [
    "source=shop-gradle-home,target=/home/vscode/.gradle,type=volume"
  ],
  "postCreateCommand": "sudo chown -R vscode /home/vscode/.gradle",
  "customizations": {
    "vscode": {
      "extensions": [
        "vscjava.vscode-java-pack",
        "vscjava.vscode-gradle",
        "vmware.vscode-boot-dev-pack"
      ]
    }
  }
}

초안에서 고칠 것은 셋이다.

초안오늘이유
"remoteUser": "vscode"뺀다6회차에 이미지 라벨 devcontainer.metadata에 "remoteUser": "vscode"가 이미 있는 것을 확인했고, 터미널의 whoami도 vscode였다
"forwardPorts": [8080]8081 + containerEnv의 SERVER_PORT8080은 spring-backend 트랙이 같은 shop을 호스트에서 띄울 때 쓴다. 이 트랙의 포트는 8081이다
chown -R-R 없이처음 만든 볼륨은 비어 있어서 폴더 하나만 바꾸면 된다. 6회차와 같은 명령

이미지 태그 25와 25-trixie는 2026-10-16에 docker buildx imagetools inspect로 보니 같은 이미지(digest sha256:da82e1…)였다. 6회차에 받은 이미지를 그대로 쓴다. 초안의 25-trixie는 Debian 버전(trixie)이 태그에 드러나서 그대로 둔다. (devcontainers/images: java)

새로 쓰는 키 두 개

  • mounts: 문자열 배열이다. 문자열 하나가 Docker CLI --mount의 값과 같은 문법이다. (devcontainer.json reference) 쉼표로 키=값을 잇는다. type은 volume이나 bind, source는 볼륨 이름(bind면 호스트 경로), target은 컨테이너 안 경로다. 볼륨이 없으면 새로 만든다. (Volumes: --mount 옵션) 6회차 Compose의 gradle-cache:/home/vscode/.gradle와 같은 일을 이미지 방식에서 한다.
  • customizations.vscode.extensions: 컨테이너가 만들어질 때 컨테이너 안에 설치할 확장 ID 목록이다. (Managing extensions) customizations 아래 도구 이름(vscode)으로 한 번 더 묶는다.

예시 (오늘 과제와 다른 Python 앱)

{
  "name": "flask-demo",
  "image": "mcr.microsoft.com/devcontainers/python:3.12",
  "mounts": [
    "source=flask-pip-cache,target=/home/vscode/.cache/pip,type=volume"
  ],                                   // 볼륨 flask-pip-cache를 pip 캐시 폴더에
  "customizations": {
    "vscode": {                        // 도구 이름으로 한 번 더 묶는다
      "extensions": ["ms-python.python"]   // 컨테이너 안에 설치할 확장
    }
  }
}

주석(//)은 설명용이다. 오늘 파일에는 쓰지 않는다.

4. 오늘 쓰는 명령

명령하는 일
git branch브랜치 목록. 지금 브랜치에 *, 다른 worktree에 꺼내진 브랜치에 +가 붙는다. (git-branch)
git worktree add--relative-paths -b 새브랜치 경로: 지금 HEAD에서 새 브랜치를 만들고, 그 브랜치를 꺼낸 새 작업 폴더를 경로에 만든다. .git 파일에는 상대 경로를 적는다. (git-worktree)
git worktree listworktree 목록. main이 먼저, 줄마다 경로·커밋·브랜치. (같은 문서)
git switch 브랜치지금 폴더를 그 브랜치로 바꾼다. (git-switch)
Get-Content 파일파일 내용 출력 (PowerShell). docs
./gradlew build컴파일, 테스트, jar 만들기를 한 번에 한다. (Java plugin: build)
git status지금 브랜치와 바뀐·새 파일. (git-status)
git add / commit커밋할 파일을 고른다(add 파일). 고른 파일로 커밋을 만든다(commit -m "메시지"). 이미 써 본 명령
git log --oneline -n 2 브랜치그 브랜치의 최근 커밋 2개를 한 줄씩. (git-log)
git -C 폴더 …그 폴더에서 친 것처럼 git을 실행한다. cd 없이 쓴다. (git -C)
git config 키그 설정의 값을 읽는다. 없으면 아무것도 출력하지 않는다. (git-config)
docker rm -f 이름실행 중이어도 끝내고 지운다. 1회차 명령
