9회차 · 호스트↔컨테이너 인수인계

오늘의 성과: 호스트 터미널에서 명령 하나로 컨테이너 Claude에게 이슈 파일을 맡긴다. 컨테이너 Claude가 커밋한 결과를 호스트에서 git으로 리뷰하고, 같은 세션에 후속 지시를 보낸다. 결과물은 shop의 README.md다.

8회차에 shop dev container(worktree projects/shop-docker-devcontainer, 브랜치 docker-devcontainer)에 Claude Code를 넣고 로그인했다. 로그인 정보는 볼륨 claude-code-config-…에 있고, containerEnv의 CLAUDE_CONFIG_DIR=/home/vscode/.claude가 그 볼륨을 가리킨다. 오늘은 그 컨테이너 Claude를 사람 대신 호스트가 부른다. 용어는 용어집을 따른다.

1. 왜 파일과 git으로 넘기나

  • 호스트 Claude와 컨테이너 Claude는 서로 메시지를 보낼 수 없다. 문서는 "A session inside a container and a session on the host can't reach each other"라고 적는다. (Cross-session messaging)
  • 둘이 함께 보는 것은 bind mount된 프로젝트 폴더다. 컨테이너에서 고친 파일은 호스트 디스크의 실제 파일이다. (Development containers, 첫 문단) 커밋도 bind mount된 common dir(projects\shop\.git → /workspaces/shop/.git)에 쌓이므로 호스트 git이 바로 본다.
  • 그래서 흐름은 이렇다.
    1. 호스트 Claude가 프로젝트 안 이슈 파일에 요구사항과 완료 기준을 쓴다.
    2. 사람이 호스트 터미널에서 docker exec … claude -p …로 컨테이너 Claude를 부른다.
    3. 컨테이너 Claude가 브랜치에 커밋하고 보고 파일을 쓴다.
    4. 호스트에서 git으로 리뷰하고, 후속 지시는 --resume으로 같은 세션에 보낸다.

2. docker exec로 컨테이너 안에 띄우기

1회차의 docker exec는 실행 중인 컨테이너에 프로세스를 하나 더 띄운다. 오늘은 옵션 세 개를 더 쓴다. (docker exec)

옵션뜻안 주면
-u 사용자그 사용자로 실행문서의 기본값 칸이 비어 있다. 실습 A에서 잰다
-w 경로그 폴더에서 실행"컨테이너를 만들 때 정한 작업 폴더"
-e 키=값이 프로세스에만 환경 변수를 더한다컨테이너를 만들 때의 환경 변수만 물려받는다
  • 8회차 실측: docker exec … printenv에 containerEnv 값은 나오고 remoteEnv 값은 나오지 않았다. 위 표 마지막 칸과 맞는다. 그래서 CLAUDE_CONFIG_DIR는 docker exec로 띄운 claude에도 보인다.
  • remoteUser(vscode)는 VS Code가 터미널과 도구를 띄울 때 쓰는 사용자다. (devcontainer.json reference) docker exec는 VS Code를 거치지 않는다.
  • 지금 shop 컨테이너를 docker inspect로 보면 Config.User가 "root", Config.WorkingDir가 ""(비어 있음)다. worktree 폴더는 /workspaces/shop-docker-devcontainer에 붙어 있다.

3. claude -p: 대화 없이 한 번 실행

  • -p(--print)는 프롬프트 하나를 받아 끝까지 일하고 결과를 출력한 뒤 끝난다. 성공하면 종료 코드 0이다. (Run Claude Code programmatically)
  • --output-format json을 주면 결과를 JSON 한 덩어리로 낸다. 오늘 읽을 필드:
    필드뜻
    resultClaude의 마지막 답
    session_id이 대화의 ID. 이어서 시킬 때 쓴다
    is_error실패했는지
    num_turns도구를 쓰며 오간 횟수
    total_cost_usd추정 비용
    permission_denials권한이 없어 거부된 도구 호출 목록

    headless 문서는 result·session_id·비용만 직접 적는다. 나머지 이름은 Agent SDK의 결과 메시지 타입에서 가져왔다. CLI 출력에 실제로 있는지는 실습 C에서 확인한다.

  • -p의 시작 모드는 대화형과 다르다. v2.1.302 이상에서 아무것도 모드를 정하지 않으면 -p는 Manual(default)로 시작한다. Manual에서 승인이 필요한 호출은 승인해 줄 것이 없으면 거부된다. (headless 문서, "Auto-approve tools") 8회차에 대화형 세션이 auto로 시작한 것과 다르다. 컨테이너의 Claude Code는 2.1.304다.
  • 미리 허락하는 방법 두 가지:
    옵션하는 일
    --allowedTools "규칙,규칙"나열한 도구만 묻지 않고 허용. Bash(git commit *)는 git commit으로 시작하는 명령. * 앞 공백이 단어 경계를 만든다. 공백이 없으면 git commit-tree처럼 이어 붙은 명령도 잡힌다
    --permission-mode auto분류기가 검사하고 통과한 것은 다 허용. -p에서도 같은 옵션이 동작한다

    출처: headless 문서 "Auto-approve tools", Permission modes

  • --permission-prompts none은 print mode에서 승인 요청에 답할 사람이 없다고 알린다. v2.1.259 이상에 있다. (CLI reference, headless 문서 "Turn off permission prompts in unattended runs") 오늘은 쓰지 않고, 컨테이너의 2.1.304 도움말에 나오는지만 본다.
  • -p는 신뢰 확인 없이 프로젝트의 .claude/settings.json hook과 .mcp.json 서버를 실행한다. (headless 문서, --bare 절) shop에는 둘 다 없다. 이것을 끄는 --bare는 구독 로그인을 쓰지 않고 API 키를 요구하므로 오늘은 쓰지 않는다.

문법 예시 (오늘 과제와 다른 Node 프로젝트)

docker exec -u node -w /workspaces/blog web-dev `   # node 사용자로, 그 폴더에서, 컨테이너 web-dev 안에
  claude -p "Fix the failing test in test/date.test.js" `   # 대화 없이 한 번
  --allowedTools "Edit,Bash(npm test *)" `                  # 수정과 npm test만 허용
  --output-format json                                      # 결과를 JSON으로

줄 끝 `는 PowerShell의 줄 잇기다. # 주석은 설명용이다. 실제로 칠 때는 한 줄로 친다.

4. 세션 이어가기와 PowerShell로 JSON 읽기

  • 세션 기록은 설정 폴더 아래 projects/<작업 폴더 경로>/<session-id>.jsonl에 저장된다. CLAUDE_CONFIG_DIR를 지정하면 그 폴더가 바뀐다. (Sessions) shop 컨테이너에서는 볼륨 안이다.
  • claude -p "다음 지시" --resume <session_id>는 그 대화에 이어서 시킨다. (headless 문서, "Continue conversations")
  • 이어 간 -p 실행은 새 -p 실행과 같은 권한 모드로 시작한다. 앞 실행에 준 권한 옵션은 다시 줘야 한다. (Sessions)
  • PowerShell에서는 출력을 ConvertFrom-Json에 넘기면 필드를 $r.session_id처럼 읽는다. (ConvertFrom-Json)
  • 실습 C의 첫 줄 [Console]::OutputEncoding = [Text.Encoding]::UTF8은 이 터미널이 외부 프로그램 출력을 UTF-8로 읽게 맞춘다. claude의 출력은 UTF-8이다. 맞추지 않으면 result의 한글이 깨질 수 있다고 보고 미리 친다(확인하지 않았다).

문법 예시: 이어서 시키기 (같은 Node 프로젝트)

$a =claude -p "List the TODOs in src/" --output-format json | ConvertFrom-Json   # 첫 실행, 객체로 받기
$a.session_id                                                                      # 그 대화의 ID 출력
$b = claude -p "Now fix the first one" --resume $a.session_id `                   # 같은 대화에 이어서
  --allowedTools "Edit" --output-format json | ConvertFrom-Json                    # 권한 옵션은 다시 준다
$b.result                                                                          # 마지막 답만 출력

5. 계정 커넥터

8회차에 확인했듯 로그인하면 claude.ai 계정의 커넥터(Claude Docs·Gmail·Notion)가 컨테이너 Claude에도 들어온다. 사람이 보지 않는 실행에서 끄는 방법은 둘이다. (MCP, "Use MCP servers from Claude.ai")

방법범위
환경 변수 ENABLE_CLAUDEAI_MCP_SERVERS=false그 프로세스만. docker exec -e로 준다
설정 "disableClaudeAiConnectors": true그 설정 파일이 적용되는 모든 세션. 어느 범위든 true가 이긴다

오늘 명령은 첫 번째 방법을 쓴다. 파일을 바꾸지 않고 오늘 실행에만 적용된다.

6. 오늘 쓰는 명령

모두 호스트 VS Code 창(이 강의 창)의 터미널 lab(PowerShell)에서 친다.

명령하는 일
docker ps --format "{{.Names}} {{.Status}}"실행 중인 컨테이너의 이름과 상태만 한 줄씩 (docker ps --format)
$c = "이름"PowerShell 변수에 컨테이너 이름을 담는다. 뒤 명령에서 $c로 쓴다
docker exec $c whoami그 컨테이너 안에서 실행한 사용자 이름
docker exec $c pwd그 프로세스의 작업 폴더
docker exec … claude --help | Select-String 문자열도움말 중 그 문자열이 든 줄만 (Select-String)
[Console]::OutputEncoding = [Text.Encoding]::UTF8외부 프로그램 출력을 UTF-8로 읽게 한다. 이 터미널에서 한 번
$r = 명령 | ConvertFrom-JsonJSON 출력을 객체로 바꿔 $r에 담는다
$r | Format-List 필드, 필드그 필드만 한 줄씩 (Format-List)
git -C 폴더 명령그 폴더에서 git을 실행한 것처럼 (git)
git log --oneline -3최근 커밋 3개를 한 줄씩 (git-log)
git show HEAD / --stat마지막 커밋의 작성자·메시지·바뀐 줄 / 바뀐 파일 목록만 (git-show)

7. 실습 — 예측하고 직접 친다

실습 창(컨테이너로 연 shop)은 컨테이너를 켜 두는 용도다. 명령은 모두 호스트의 이 창 터미널 lab에서 친다. 명령마다 먼저 Clear-Host를 치고, 출력은 @terminal:lab으로 붙인다.

A. 컨테이너를 켜고, docker exec가 누구로 도는지 재기

  1. 실습 창을 연다. 왼쪽 아래가 Dev Container: shop이 아니면 F1 → Dev Containers: Reopen in Container.

    code -n E:\Study\Inflearn\projects\shop-docker-devcontainer

    호스트 터미널 lab에서 컨테이너 이름을 확인하고 변수에 담는다. 8회차 끝의 이름은 interesting_carson이었다. Rebuild하지 않았으면 같다.

    docker ps --format "{{.Names}}  {{.Status}}"
$c = "interesting_carson"

  2. 옵션 없이 사용자·작업 폴더·환경 변수를 본다.

    docker exec $c whoami
docker exec $c pwd
docker exec $c printenv HOME CLAUDE_CONFIG_DIR
    재료: shop 컨테이너의 Config.User는 "root", Config.WorkingDir는 비어 있다. docker exec 문서의 예시에서 작업 폴더를 정하지 않은 컨테이너의 pwd는 /이고, root로 돈 env에는 HOME=/root가 나온다. containerEnv 값은 docker exec에도 보인다. 세 명령은 각각 무엇을 출력할까?

  3. 사용자와 폴더를 정해서 다시 본다.

    docker exec -u vscode -w /workspaces/shop-docker-devcontainer $c whoami
docker exec -u vscode -w /workspaces/shop-docker-devcontainer $c pwd
docker exec -u vscode $c printenv HOME

    확인 거리: -u vscode만 줘도 HOME이 바뀌는가. 문서에 없어서 예측하지 않고 결과를 본다.

    2단계와 3단계 결과를 놓고 Claude와 이야기한다. root로 claude를 띄웠다면 홈 폴더, CLAUDE_CONFIG_DIR, 컨테이너 Claude가 만든 파일의 소유자 중 무엇이 어긋났을까?

    이어서 컨테이너 Claude의 도움말에서 permission이 든 줄만 본다. 3절의 --permission-prompts가 이 버전에 있는지 확인한다. claude를 못 찾는다는 오류가 나면 출력을 붙여 넣고 멈춘다.

    docker exec -u vscode $c claude --help | Select-String "permission"

$r = docker exec -u vscode -w /workspaces/shop-docker-devcontainer -e ENABLE_CLAUDEAI_MCP_SERVERS=false $c claude -p "Read .scratch/dev-container-readme/issue.md and do what it says." --output-format json | ConvertFrom-Json

D. 이어서: 필요한 권한만 주고 --resume

  1. 같은 세션에 이어서 시킨다. 이번에는 파일 쓰기·고치기와 git add·git commit만 허용한다.

    $r2 = docker exec -u vscode -w /workspaces/shop-docker-devcontainer -e ENABLE_CLAUDEAI_MCP_SERVERS=false $c claude -p "You now have permission. Finish the task." --resume $r.session_id --allowedTools "Write,Edit,Bash(git add *),Bash(git commit *)" --output-format json | ConvertFrom-Json
$r2 | Format-List result, session_id, num_turns, total_cost_usd
$r2.permission_denials
    프롬프트에 이슈 파일 이름이 없다. 컨테이너 Claude는 무엇을 할지 알까? $r2.session_id는 $r.session_id와 같을까? permission_denials는 비어 있을까?

E. 호스트에서 리뷰하고 후속 지시

  1. 위에서부터: 최근 커밋 3개, 마지막 커밋의 작성자·메시지·바뀐 파일 목록, 남은 변경.

    git -C E:\Study\Inflearn\projects\shop-docker-devcontainer log --oneline -3
git -C E:\Study\Inflearn\projects\shop-docker-devcontainer show --stat HEAD
git -C E:\Study\Inflearn\projects\shop-docker-devcontainer status --short
    커밋 작성자는 누구로 찍힐까? (7회차: Dev Containers는 사용자 .gitconfig를 컨테이너로 복사한다) status에는 무엇이 남을까?

    이어서 git show HEAD로 본문을 Claude와 함께 읽는다. README의 문장마다 devcontainer.json의 어느 줄이 근거인지, 근거 없는 문장은 없는지 본다. report.md의 "확인하지 못한 것"도 읽는다.

  2. 시간이 남으면. 리뷰에서 고칠 점을 정하면 같은 세션에 보낸다. 지시 문장은 리뷰 뒤에 Claude와 함께 정한다. 이어 갈 ID는 가장 최근 실행의 $r2.session_id다.

    $r3 = docker exec -u vscode -w /workspaces/shop-docker-devcontainer -e ENABLE_CLAUDEAI_MCP_SERVERS=false $c claude -p "리뷰 지시" --resume $r2.session_id --allowedTools "Write,Edit,Bash(git add *),Bash(git commit *)" --output-format json | ConvertFrom-Json
$r3.result

    끝나면 7단계의 log와 show --stat를 다시 본다.

실습에서 드러난 것 (2026-10-21). 옵션 없는 docker exec는 root, 작업 폴더 /, HOME=/root였다. -u vscode만 줘도 HOME=/home/vscode가 된다. 2.1.304 도움말에 --permission-prompts(host·none, 기본 host)가 있고, --permission-mode 목록에는 default 대신 manual이 있다. 권한 옵션 없는 첫 실행은 거부 5건(Bash 3, Write 2)으로 아무것도 바꾸지 못했는데 is_error는 False였다. 판정은 permission_denials와 git으로 한다. --resume은 같은 session_id를 이어 썼다. 리뷰 반영은 amend가 아니라 새 커밋(710a74a)이었다. 허용 목록은 할 수 있는 범위만 정한다.
