6회차 · Dev Container 기초

오늘의 성과: docker-lab을 컨테이너 안에서 열고, 호스트 JDK가 아닌 컨테이너의 JDK로 ./gradlew bootRun을 돌린다. 그 앱을 5회차 compose.yaml의 db에 붙여 memo 테이블의 값을 브라우저에 띄운다.

4회차에는 호스트에서 jar를 만들어 이미지에 넣었다. 그 이미지는 앱을 실행하는 환경이다. 오늘은 앱을 개발하는 환경(JDK, Gradle, 터미널, 확장)을 컨테이너로 만든다. 그 설정을 파일로 남기면 어느 PC에서나 같은 개발 환경이 뜬다. 7회차에는 같은 방법을 shop에 적용한다. 용어는 용어집을 따른다.

1. Dev container는 무엇이 다른가

  • VS Code는 확장을 "로컬(UI 쪽)" 또는 "컨테이너 안" 두 곳 중 한 곳에서 돌린다. 테마 같은 UI 확장은 로컬에, 대부분의 확장은 컨테이너에 설치된다. (Managing extensions)
  • 작업 폴더는 2회차의 bind mount로 연결된다. 그래서 컨테이너 안에서 고친 파일이 호스트 폴더에 바로 보인다.
4·5회차 앱 이미지 (app)오늘의 dev container (dev)
목적만든 앱을 실행한다앱을 고치고 빌드하고 실행해 본다
안에 든 것JRE + 호스트에서 만든 jarJDK, Git 등 개발 도구. 소스는 bind mount
주 프로세스java -jar …할 일 없이 기다리는 명령. 작업은 터미널에서 직접 친다
코드를 고치면jar를 다시 만들고 이미지를 다시 빌드한다파일이 바로 보인다. ./gradlew를 다시 돌린다

2. 이미지에 적힌 사용자와 기본 명령

오늘 쓰는 이미지는 mcr.microsoft.com/devcontainers/java:25다. Java 25 태그는 25, 25-trixie, 25-bookworm이 있다. (devcontainers/images: java) 레지스트리에 있는 이 이미지의 설정을 2026-10-15에 읽어 보니 아래와 같았다.

설정값
사용자 (User)root
기본 명령 (Cmd)bash
라벨 devcontainer.metadata"remoteUser": "vscode" 등
  • 사용자: remoteUser는 VS Code가 컨테이너 안에서 터미널과 도구를 실행할 사용자다. 지정하지 않으면 컨테이너 전체를 실행하는 사용자(대개 root)다. (devcontainer.json reference) 이 이미지는 라벨에 remoteUser를 적어 두었다. 컨테이너는 root로 뜨지만 터미널은 다른 사용자일 수 있다. 실습 B-5에서 확인한다.
  • 기본 명령: 1회차에서 봤듯이 주 프로세스가 끝나면 컨테이너는 exited가 된다. dev container 도구는 이미지의 기본 명령을 자기 명령으로 덮어써서 컨테이너가 계속 떠 있게 할 수 있다. 이것이 overrideCommand다. 기본값은 image를 쓸 때 true, Compose 파일을 쓸 때 false다. (devcontainer.json reference)
  • 그래서 Compose로 띄울 때는 서비스에 기다리는 명령을 직접 적는다. VS Code 문서 예제는 "프로세스가 끝나도 컨테이너가 내려가지 않게 기본 명령을 덮어쓴다"는 주석과 함께 반복 sleep을 쓴다. (Use Docker Compose) 오늘은 같은 목적으로 sleep infinity를 쓴다.

3. 포트: forward와 publish

forward (forwardPorts)publish (Compose ports, 3회차 -p)
누가 연결하나VS Code가 자기 연결을 통해 전달한다Docker가 호스트 포트를 연다
앱이 보기에접속이 localhost에서 온 것처럼 보인다로컬 네트워크에 연 포트처럼 동작한다

표는 Forwarding or publishing a port의 설명이다.

forward하려는 로컬 포트가 이미 쓰이고 있으면, 기본값에서는 알리지 않고 다른 로컬 포트로 연결한다. (requireLocalPort, 기본값 false) 그래서 브라우저 주소가 예상과 다를 수 있다.

이 트랙의 포트는 8081이다. 8080은 spring-backend 트랙이 쓴다. Spring Boot는 환경 변수 SERVER_PORT로 포트를 바꿀 수 있다(4회차에 SPRING_DATASOURCE_URL로 DB 주소를 바꾼 것과 같은 방식). (Change the HTTP Port)

4. Gradle 캐시를 named volume에 두는 이유

  • Gradle은 내려받은 Gradle 배포판과 라이브러리를 사용자 홈의 ~/.gradle에 둔다. (Gradle directories)
  • 그 폴더가 컨테이너의 쓰기 가능한 레이어에 있으면 2회차처럼 컨테이너를 다시 만들 때 사라진다. Rebuild할 때마다 전부 다시 내려받는다.
  • 호스트 폴더를 bind mount하는 방법도 있지만, Windows에서는 컨테이너가 VM 안에서 돌기 때문에 bind mount가 컨테이너 파일시스템보다 느리다. (Improve container performance)
  • 그래서 문서는 자주 읽고 쓰는 폴더 하나에 named volume을 붙이는 방법("Use a targeted named volume")을 보인다. 문서 예제는 non-root 사용자일 때 postCreateCommand에서 sudo chown으로 그 폴더의 소유자를 바꾼다. (Use a targeted named volume)
  • postCreateCommand는 컨테이너를 처음 만들 때 설정 마지막에 한 번 실행하는 명령이다. (Lifecycle scripts)

5. devcontainer.json 쓰는 법

프로젝트 폴더 안 .devcontainer/devcontainer.json에 둔다. (Create a devcontainer.json file) JSON 규칙은 다섯 가지다. (JSON 소개)

  • 전체를 { }로 감싼다.
  • 키와 문자열은 큰따옴표로 감싼다. 숫자는 감싸지 않는다.
  • 항목 사이에 쉼표. 마지막 항목 뒤에는 쉼표를 쓰지 않는다.
  • 목록은 [ ], 묶음은 { }.
  • YAML과 달리 들여쓰기는 뜻이 없다. 읽기 좋게만 맞춘다.

예시 1: 이미지 하나로 (오늘 과제와 다른 Python 앱)

{
  "name": "flask-demo",
  "image": "mcr.microsoft.com/devcontainers/python:3.12",
  "forwardPorts": [5000],
  "containerEnv": {
    "FLASK_DEBUG": "1"
  }
}
키뜻
nameVS Code 화면에 보이는 이름
image컨테이너를 만들 이미지. 이미지 방식에서는 필수다
forwardPorts늘 forward할 컨테이너 포트 목록. 숫자 배열이다
containerEnv컨테이너 자체에 넣는 환경 변수. 바꾸면 Rebuild해야 반영된다. 값은 문자열로 쓴다

예시 2: Compose 파일로 (같은 Python 앱 + redis)

compose.yaml (프로젝트 폴더 맨 위):

services:
  web:                          # 운영용: 이미지를 빌드해 실행
    build: .
    ports:
      - "8000:5000"
  devbox:                       # 개발용: 도구만 있고 기다린다
    image: mcr.microsoft.com/devcontainers/python:3.12
    command: sleep infinity     # 주 프로세스가 끝나지 않게
    volumes:
      - .:/workspaces/flask-demo          # 소스 bind mount
      - pipcache:/home/vscode/.cache/pip  # 캐시 named volume
    environment:
      CACHE_HOST: cache
  cache:
    image: redis:7

volumes:
  pipcache:

.devcontainer/devcontainer.json:

{
  "name": "flask-demo",
  "dockerComposeFile": "../compose.yaml",
  "service": "devbox",
  "runServices": ["devbox", "cache"],
  "workspaceFolder": "/workspaces/flask-demo",
  "forwardPorts": [5000],
  "postCreateCommand": "sudo chown vscode /home/vscode/.cache/pip"
}
키뜻
dockerComposeFileCompose 파일 경로. devcontainer.json이 있는 폴더 기준이다. 그래서 한 단계 위는 ../
serviceVS Code가 붙을 서비스. Compose 방식에서는 필수다
runServices시작할 서비스 목록. 생략하면 전부 시작한다. 위에서는 운영용 web을 뺐다
workspaceFolderVS Code가 컨테이너 안에서 열 경로. Compose 방식의 기본값은 /라서 직접 적는다. Compose 파일의 bind mount 대상 경로와 같게 쓴다
postCreateCommand컨테이너를 처음 만든 뒤 한 번 실행할 명령
  • Compose 방식에서는 소스 bind mount를 Compose 파일의 volumes에 직접 적는다. (Use Docker Compose)
  • Compose 방식에서 창을 닫으면 기본값(shutdownAction: stopCompose)에 따라 Compose 컨테이너를 멈춘다. 이미지 방식의 기본값은 stopContainer다. (devcontainer.json reference)
  • 키 전체 목록은 devcontainer.json reference에 있다.
