# 새 강좌 도입

새 강좌 자료가 들어왔을 때 따른다. 결과물은 `courses/<course>/`와 트랙 배정에 대한 사용자 결정이다. 트랙 설계는 [track-design.md](track-design.md)에서 한다.

## 1. 배치

- `<course>`는 강좌명 기준 영어 kebab-case로 짓는다(`spring-db1`).
- 원본은 `courses/<course>/pdf/`에, 예제 프로젝트는 `courses/<course>/code/`에 둔다.
- 완료: 받은 자료가 모두 두 폴더 중 하나에 있다.

## 2. 변환

- pdf-to-markdown 스킬로 `pdf/` 전체를 `docs/`로 변환한다.
- 완료: 리포트의 ERROR가 0이다. WARN마다 원인과 읽을 때 주의할 점이 README "변환 메모"에 있다.

## 3. 분석

`docs/`를 장마다 읽고 `courses/<course>/README.md`에 적는다. 어느 트랙에도 속하지 않는 사실만 적는다.

- 교재 버전, 교재가 전제하는 버전(언어, 프레임워크, DB).
- 장 표: `장 | 제목 | 줄 수 | 핵심 주제 한 줄 | 선행 장 | 예제 프로젝트`.
- 현재 최신 안정 버전과의 차이: 공식 문서로 확인한 것만 출처와 함께 적는다. 확인하지 못한 것은 "미확인"으로 적는다.
- 예제 코드 상태: 빌드 가능 여부, 교재가 언급하지만 폴더에 없는 프로젝트.
- 다른 강좌와 겹치는 범위: 다른 `courses/*/README.md`의 장 표와 대조한 결과.
- 완료: 모든 장이 장 표에 한 줄씩 있고, 버전 차이 항목마다 출처나 "미확인"이 붙어 있다.

## 4. 버전 점검

- [versions.md](versions.md)의 "버전 점검"을 따른다.
- 완료: 그 절의 완료 조건을 만족한다.

## 5. 트랙 배정 제안

분석을 근거로 아래 선택지를 사용자에게 제시한다. 결정은 사용자가 한다.

- 기존 트랙에 추가: 어느 트랙의 어느 회차 뒤에 붙는지, 겹치는 장을 어떻게 다룰지.
- 새 트랙: [track-design.md](track-design.md)로 넘어간다.
- 여러 트랙으로 분할: 장 범위를 트랙별로 어떻게 나누는지.
- 완료: 사용자가 결정했다. 기존 트랙에 추가하기로 했다면 `TRACKS.md`의 강좌(장)와 그 트랙 `NOTES.md`의 커리큘럼이 갱신됐다.
