# 학습 운영 규칙

## 구조

| 층 | 위치 | 담는 것 |
|---|---|---|
| 자료 | `courses/<course>/` | 원본 `pdf/`, 변환 `docs/`, 예제 `code/`, 강좌 분석 `README.md`. 어느 트랙에도 속하지 않는 사실만 담는다. |
| 학습 | `lecture/<track>/` | teach 학습 공간 하나. `MISSION.md`, `NOTES.md`, `RESOURCES.md`, `learning-records/`, `lessons/`, `reference/`, `assets/`. |
| 실습 | `projects/<project>/` | 독립 git repo. `.devcontainer/`를 두고 dev container 안에서 빌드·실행한다. 두 트랙이 한 repo를 쓰면 트랙마다 git worktree를 둔다. |
| 색인 | `lecture/TRACKS.md` | 트랙과 강좌·프로젝트·실행 자원의 대응. |
| 도구 | `.tools/<tool>/` | 어느 트랙에도 속하지 않는 로컬 실행 파일. git에 넣지 않고, 버전은 `versions.toml`에 등록한다. 쓰는 방법은 그 도구를 부르는 스크립트와 트랙 `NOTES.md`에 적는다. |

- **트랙**은 MISSION 하나와 커리큘럼 하나의 단위다. 강좌와 트랙은 다대다다. 강좌 여러 개가 한 트랙이 되고, 강좌 하나가 여러 트랙으로 나뉜다. 이 대응은 `TRACKS.md`에만 적는다.
- 트랙 이름은 목표 기준 영어 kebab-case로 짓는다(`spring-backend`). 강좌명으로 지으면 강좌가 더해지거나 나뉠 때 이름이 틀려진다.

## TRACKS.md 형식

```md
| 트랙 | 상태 | 강좌(장) | 프로젝트 작업 폴더 | 포트 | DB |
|---|---|---|---|---|---|
| spring-backend | 진행 중 | spring-mvc2(1–11), spring-db1(1–6) | projects/shop | 8081 | shop |
```

- 상태: 설계 중 / 진행 중 / 일시 중지 / 완료.
- 포트와 DB 이름은 트랙마다 다르게 배정한다. 완료된 트랙의 포트는 다른 트랙에 넘길 수 있다. 넘긴 칸에는 `(반납)`을 붙인다.
- 같은 장을 두 트랙이 쓰면 두 행 모두에 적는다.

## 강의 세션 규칙

다른 트랙의 강의 세션이 동시에 돌고 있다고 가정하고 따른다.

1. 트랙을 먼저 확정한다. teach 인자가 트랙 이름이면 그 트랙이다. 아니면 `TRACKS.md`의 "진행 중" 트랙을 보여주고 묻는다. 확정 전에는 파일을 쓰지 않는다.
2. `lecture/<track>/NOTES.md`의 "현재 위치"부터 잇는다.
3. 쓰기는 자기 트랙 폴더와 `TRACKS.md`에 적힌 자기 프로젝트 작업 폴더 안에서만 한다. 그 밖의 파일은 읽기만 한다. 그쪽에 고칠 것이 생기면 자기 `NOTES.md`의 "공유 파일 변경 요청"에 적고 사용자에게 알린다.
4. 다음에 가르칠 것을 정할 때 다른 트랙의 `learning-records/`도 읽는다. 다른 트랙에서 이해가 증명된 내용은 다시 가르치지 않는다. 인용할 때는 `spring-backend/0003`처럼 트랙 이름을 붙인다.
5. 앱과 DB는 프로젝트의 dev container 안에서, `TRACKS.md`에 배정된 포트와 DB 이름으로 실행한다.
6. 커밋은 자기 프로젝트 작업 폴더에서만 한다. Gradle 프로젝트를 새로 만들면 첫 커밋 전에 [versions.md](versions.md)의 "새 Gradle 프로젝트"를 따른다.
7. 회차를 마칠 때, 커밋하기 전에 자기 트랙 폴더의 마크다운을 정리한다. 정리 대상은 다음과 같다.
   - 끝난 일을 위한 줄
   - 다른 문서와 의미가 겹치는 줄. 기준 문서 쪽만 남긴다.
   - 현재 구조와 맞지 않는 경로나 회차 번호
   - 전역·프로젝트 지침과 같은 내용의 줄
   - 아무 데서도 참조하지 않는 파일

   learning-records, MISSION의 기록, 앞으로의 계획, 미확인 목록은 남긴다. 트랙 밖 파일에서 찾은 정리 거리는 3번에 따라 "공유 파일 변경 요청"에 적는다. 지운 것과 고친 것은 사용자에게 3줄 이내로 알린다.

## 레슨 설계

학습자는 사람이다. 처음 보는 문법을 조건만 보고 쓰지 못하고, 앞 회차 자료를 찾아 대조하는 데 작업 기억을 쓴다.

- 새 개념을 실습에서 쓰게 하면 그 사용법을 먼저 넣는다: 문법 규칙, 과제와 다른 예시 하나(줄마다 뜻을 주석으로), 공식 문서 링크.
- 과제를 내는 레슨에는 그 레슨만 보고 풀 수 있게 조건을 모두 적는다: 써야 할 값, 이름, 요구 사항.
- 앞 회차 내용이 필요하면 "N회차 X 참고"로 가리키지 않고 그 내용(명령, 값, 결론)을 그 자리에 다시 적는다. 채팅도 같다.
- 채팅은 레슨 HTML 없이도 따라갈 수 있게 쓴다. 레슨은 참고 자료다. 레슨의 절·단계 번호("5절 표", "A-1 조건표")를 가리키지 않고 그 표·규칙·값을 채팅에 적는다.

## 강의 세션의 위임

이 절은 전역 오케스트레이션 규칙과 다른 점만 적는다. `source-reader`와 `visual-reviewer`는 `.claude/agents/`에 있는 이 프로젝트 전용 역할이다.

| 작업 | 담당 |
|---|---|
| 회차 1차 자료 읽기(강좌 장 md, 웹 공식 문서) | source-reader. 메인은 반환된 줄 범위·URL 중 레슨에 옮길 부분만 직접 읽는다. 미확인 항목이나 반환에 없는 사실은 직접 찾지 말고 source-reader를 재개해 묻는다. |
| 강좌 전체 분석([course-intake.md](course-intake.md)) | source-reader를 장 묶음별로 나눠 병렬로 돌린다. |
| 연습 채점, 예제 코드 검토 | reviewer. 브리프에 [grading.md](grading.md), 채점할 파일 경로(또는 diff), 그 회차의 강좌 자료 경로를 준다. 사용자와 리뷰 대화는 메인이 그 결과와 diff로 한다. |
| 다른 트랙 learning-records 대조 | explorer. 브리프에 이번 회차 후보 개념 목록을 주고 `개념 \| 기록 경로:줄 \| 근거 인용` 형식으로 후보만 받는다. 이미 증명됐는지는 메인이 판단한다. |
| 레슨 검토 | [lesson-review.md](lesson-review.md) 순서대로. 내용은 reviewer, 시각은 visual-reviewer. 사용자에게 열기 전에 한다. |

메인이 직접 하는 위임 예외:
- 설명, 질의응답, 사용자와 리뷰 대화.
- 조사 직후 같은 맥락에서 하는 회차 레슨 작성. 그 레슨의 검토 지적 수정과 용어집 갱신도 포함한다.
- 트랙 `NOTES.md` "명령 실행"의 기준에 맞는 상태 확인 읽기 명령.

트랙 `NOTES.md`에는 이 절과 다른 트랙 고유의 위임 규칙만 적는다.

## 공유 파일 변경

`TRACKS.md`, `CLAUDE.md`, memory, `courses/`, `references/`, `docs/`, `.tools/`, `versions.toml`은 강의가 아닌 세션에서 고친다.

- 새 강좌 자료가 들어오면 [course-intake.md](course-intake.md)를 따른다.
- 새 트랙을 만들면 [track-design.md](track-design.md)를 따른다.
- 진행 중인 트랙의 파일을 고칠 때는 그 트랙의 강의 세션이 돌고 있지 않은지 사용자에게 확인한다.
